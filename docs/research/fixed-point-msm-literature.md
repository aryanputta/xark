# Fixed-point MSM and bounded bucket memory for Privacy Rings

**Claim under review.** A proving-key B2 query repeats the same BN254 G2 bases for different witness scalars. Fixed-point MSM can move some group work to key preparation. Its live table traffic, recoding, and bucket costs determine whether it improves verified proving on Xark. AdaptiveSetBucket addresses a different condition, a binding cap on live bucket memory.

## Shared construction

For points `P[i]`, construct `T[i,j,m] = [m q^j]P[i]` once per key for radix `q` and multiplier set `M`. In the integer schemes, brackets mean scalar multiplication. In the Eisenstein schemes, they mean the group action obtained by evaluating `ω` at a verified endomorphism. Recode each scalar, or its Eisenstein lift, into `sum(u[j] m[j] b[j] q^j) + κ[h] q^h`. Signs or units `u` can be applied to the point at lookup. A nonzero top residual must be evaluated explicitly and included in the preparation and timing model.

```text
for each i:
    κ = lift(a[i])
    for j in 0 .. h-1:
        select u, m, b so κ ≡ u*m*b (mod q)
        κ = (κ - u*m*b) / q
        if b != 0: S[b] += [u]T[i,j,m]
    tail += [κ*q^h]P[i]

suffix = 0
for k from last bucket to first nonzero bucket:
    suffix += S[b[k]]
    D[b[k] - b[k-1]] += suffix  # b[0] = 0
return tail + sum([δ]D[δ] for each difference class δ)
```

The suffix identity is `sum([b[k]] S[b[k]]) = sum([b[k] - b[k-1]] sum(S[b[t]], t >= k))`. Integer buckets are sorted. Eisenstein buckets can follow any complete path beginning at zero. The path controls the cost of the distinct difference actions and leaves the identity unchanged. The pseudocode starts from a running residual and describes an exact implementation after choosing a valid construction and top treatment. It does not encode the original LFG power-of-two bucket recipe. [Luo/Fu/Gong §4](https://d-nb.info/1286957532/34#page=9) · [Fan et al. §5](https://eprint.iacr.org/2024/750) · [Le/Sica Algorithms 2 and 5](https://opencryptology.org/2026/1902.pdf)

## Four primary sources

**Luo, Fu and Gong, CHES 2023.** With integer `q` and `h = ceil(log_q r)`, precompute `nh|M|` shifted multiple points. The sign-folded `{1,2,3}` example stores `3nh`. Bucket fill accumulates at most `nh` terms, followed by sorted suffix sums and weighted difference classes. Algorithm 3 gives `2m+d−3` additions for `m` nonzero buckets and max gap `d` under its counting conditions. The paper's approximate `nh + 0.21q` headline is for its original power-of-two set. Fan et al. show that set misses residues. Use the repaired variant for correctness and compare it with the pre-shifted Pippenger control, which stores `nh` points. Read the full publisher article through the German National Library mirror. [Luo/Fu/Gong, §4 and Table 1](https://d-nb.info/1286957532/34) · [Fan et al., §3](https://eprint.iacr.org/2024/750)

**Fan, Kuchta, Sica and Xu, ePrint 2024/750.** Section 3 restores missing integer residue classes and includes the carry. The repaired LFG model uses `3nh+n` points and `n(h+1)+0.21875q` group additions. Section 4 uses integer prime-power radices and the necessary counting bound `2|M||B| >= q` for signed coverage. For the paper's `p>2` construction, Table 1 lists `n(h+1)|M|` points and `n(h+1)+q/(2|M|)+p−4` additions. Section 5 lifts scalars to `Z[ω]` with `ω²+ω+1=0`, chooses `q=(2−ω)^c`, `N(q)=7^c`, and uses the six units `±1, ±ω, ±ω²` with `M={1}`. This replaces multiplier-indexed table entries with unit actions. The lift and controlled division in Algorithms 7–8 bound the top residual. Le/Sica revise the FKSX disk bucket estimate to coefficient `π/(9 sqrt(3)) ≈ 0.2015` on `N(q)` in their comparison. Read the indexed full ePrint PDF. A direct PDF request failed in this environment. [Fan et al., ePrint and source PDF](https://eprint.iacr.org/2024/750) · [Le/Sica Table 1 correction](https://opencryptology.org/2026/1902.pdf#page=3)

**Le and Sica, ePrint 2026/1902.** For `p=2−ω`, `q=p^c`, and `M={1}`, Theorem 1 gives exactly `1+(7^c−1)/6` buckets including zero. The construction takes hexagonal representatives stratified by the power of `p` dividing the residue. Theorem 2 orders them along a Hamiltonian path with max squared step `13·7/4`. At a high level, build a unit-step path on the lower-radix hexagon, rescale into the first stratum, insert the remaining strata in local triangles, then form difference accumulators along the path. Theorem 3 generalizes to an Eisenstein prime of rational norm `ℓ≡1 mod 6`, with `|M|=(ℓ−1)/6`, bucket count `1+(ℓ^c−1)/(6|M|)` and max squared step `13ℓ/4`. Table 1 models `nh+N(q)/6+81` group operations for `ℓ=7`, counting doubling as one addition, with `nh` precomputed points for the specified BLS12-381 parameters except the `c=7` top-residual case. Table 4 is theoretical over `n=2^10..2^21` and optimizes `c` by point-operation counts. The roughly 67% storage reduction versus repaired LFG counts precomputed points alone. The author-linked Sage code generates paths and count tables. No comparable Privacy Rings runtime samples or timing uncertainty were reported in this evidence. Read the complete 37-page text. [Le/Sica Theorems 1–3 and Tables 1, 4](https://opencryptology.org/2026/1902.pdf) · [Author SageMath repository](https://github.com/hoainam-le/msm_opt_buckets)

**Noël and Plantard, ePrint 2026/1316 and Journal of Cryptographic Engineering.** AdaptiveSetBucket retains a logical unsigned window `Q=2^w` while allocating `d` physical buckets. For each high-to-low window, multiply the accumulated result by `Q`, reset the running suffix, then process disjoint bucket ranges from `Q−1` down to `1`. In each range, reset the `d` slots, rescan all digits, fill only in-range buckets, and consume slots in descending order by `suffix += bucket; result += suffix`. Preserve the suffix across ranges. Algorithm 4 uses `d+2` points for bucket and accumulator state, excluding bases and scalars. With `s=ceil(bitlength/w)`, the loop performs at most `2ns ceil((Q−1)/d)` range comparisons. A direct loop accounting permits up to `ns` bucket fills and `2s(Q−1)` suffix additions before skipping zero work, plus at most `sw` doublings. Smaller `d` raises the rescans. In Table 2 for 8,192 random BLS12-381 base-field points, RELIC on an Intel Core i5-7500 reports 234,968→188,185 average cycles at 15 KB (19.91%) and 162,334→162,359 at 175 KB (0.02% slower). It uses 30 fresh, paired random scalar inputs per parameter setting and reports the lower of two run means, with no per-sample tails. The cap is on bucket storage. Read the full final article from the author's site. [Noël/Plantard Algorithm 4 and Table 2](https://thomas-plantard.github.io/pdf/NoePla26.pdf#page=8) · [ePrint record](https://eprint.iacr.org/2026/1316)

For B2 the Eisenstein `h` uses the exact BN254 scalar order and base `7^c`. The `nh` calculations are conditional on implementing the paper's scalar lift and recoding bounds on this subgroup. Substituting the BN254 scalar order into Le/Sica Equation (10) with `M={1}` gives residual absolute-value bounds 0.725, 0.596 and 0.585 rounded upward for `c=4,5,6`, respectively. Any Eisenstein integer of absolute value below one is zero. At `c=5`, 2,802 logical buckets include zero. A three-coordinate G2 projective payload of 192 bytes would imply about 0.51 MiB for the 2,801 nonzero buckets before tags, padding, scratch or worker duplication. The configuration with the smallest table can increase bucket work considerably, so the table alone cannot pick `c`. [Le/Sica Equation (10)](https://opencryptology.org/2026/1902.pdf#page=27)

## Implementation and evidence gates

1. **Start with fixed resident B2 and one warm microbenchmark.** Use the current GLV, signed-window and batch-affine path as the control. Add an unmodified shifted Pippenger arm if practical to isolate the value of hexagonal grouping from the value of shifting points. Implement the `M={1}, c=5` scalar recoder and exact bucket reference on public vectors first. Exhaust all `7^5` residues for coverage, check path cardinality and step bounds, reconstruct scalars modulo `r`, and compare group outputs with Arkworks for zero, one, `r−1`, infinity, repeated bases and boundary digits. Use the actual BN254 G2 endomorphism and check its eigenvalue/action on the generator and representative subgroup points, including `φ²+φ+Id=0`. Do not reuse the BLS12-381 twist constants. [Xark GLV and affine buckets](../../crates/groth16/src/msm.rs) · [Le/Sica reference implementation](https://github.com/hoainam-le/msm_opt_buckets)
2. **Measure the whole cost.** Use byte-identical ordered B2 inputs and the same declared CPU flags and worker budget within each paired process order. Run real escrow and withdrawal fixtures after correctness smoke. Include fresh distinct witness fixtures wherever available and report repeats of one witness separately. Record cold table build/load, bytes per key, peak RSS, warm p50 and p95, throughput under 1/4/16/64 batch sizes, and recoding, generation, gather and reduction phases for diagnostics. Use at least 30 warm samples per arm, 100+ for a tail decision, an independent result check outside the kernel timer, and verified full proofs with fresh prover randomness before recommending production changes. Time key build/load separately and estimate proof-count break-even as `ceil(extra_prepare_ms / saved_warm_ms)`, defined only for a positive saving. Keep witness vectors and traces restricted according to the existing benchmark. The best existing paired G2 signal is withdrawal. Escrow B2 reverses ordering between the two published process orders, and activity outside the VM is unknown. [Prior Xark/Gnark same-vector protocol and results](/Users/srini/xark-sprint/evidence/benchmark-lab/2026-11-25-colab-gnark-query-msm/README.md)
3. **Keep adaptive buckets a memory-cap arm.** First inspect the actual live B2 bucket allocation and select a cap that makes the default width infeasible. Compare the existing feasible narrower window with a cap-matched sharded experiment, recording scan traffic and latency as well as allocated bytes. Use a separate resource budget from fixed-point preparation. Current Xark Booth digits, GLV halves and affine batch queues require a fresh equivalence check for a sharded implementation. The papers provide no direct evidence for concurrent lookup patterns on private Privacy Rings scalars. Treat variable-time addressing and shared table behavior as a release review item before proposing any deployment, especially shared-tenant proving.
